; Task.Run moves work to a thread-pool thread. Gameplay state belongs to the map tick that owns it
; (PLAN.md §4.2), so a bare Task.Run is either a data race waiting to happen or a sign the work
; wants to be scheduled on the tick instead. Use the tick scheduler; for genuinely off-tick work
; such as database I/O, await the asynchronous API directly rather than wrapping a blocking one.
